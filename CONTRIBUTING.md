# 🤝 Contribuindo para o AI-Assisted Dev Lab

Obrigado(a) por considerar contribuir!  
Este repositório é um laboratório colaborativo onde exploramos **desenvolvimento assistido por IA**, documentamos processos, compartilhamos aprendizados e fortalecemos a comunidade de pessoas aprendendo IA.

Toda contribuição — pequena ou grande — é bem-vinda.  
Este guia existe para tornar sua participação simples, clara e acolhedora.

---

## 🟦 Antes de Começar

1. Leia o **README.md** para entender o propósito do repositório.  
2. Leia o **CODE_OF_CONDUCT.md** para garantir que estamos alinhados com o ambiente seguro e respeitoso que buscamos construir.  
3. Confira as **issues abertas** antes de criar uma nova. Talvez alguém já esteja trabalhando em algo parecido.  
4. Se for sua primeira contribuição:  
   - Use as issues marcadas com `good first issue`  
   - Entre no mural de ideias para sugerir projetos iniciais

---

## 🟧 Formas de Contribuir

Você pode contribuir de várias maneiras:

### 📝 1. Melhorando Documentação
- Corrigindo links, erros de digitação ou formatação  
- Aprimorando explicações nos READMEs  
- Reescrevendo seções para ficarem mais claras para iniciantes  
- Criando guias dentro de `/resources`  

### 💡 2. Sugerindo Novos Projetos
- Abrindo uma issue no *Mural de Ideias*  
- Propondo temas para estudos, ferramentas, pequenos apps, explorações com IA  
- Criando protótipos ou estudos iniciais  

### 🧪 3. Contribuindo com Código
- Corrigindo bugs  
- Adicionando melhorias  
- Criando novos exemplos ou funcionalidades  
- Refatorando projetos com melhores práticas  
- Adicionando testes ou scripts auxiliares  

### 🤖 4. Compartilhando Experimentos com IA
- Adicionando novas pastas de projetos  
- Compartilhando seus prompts e iterações  
- Escrevendo insights sobre sua experiência  
- Comparando abordagens diferentes para o mesmo problema  

### 🎨 5. Melhorando a Experiência de Uso
- Ajustando organização do repositório  
- Criando templates  
- Melhorando estrutura de pasta dos projetos  
- Sugestões sobre navegação e didática  

---

## 🟪 Como Abrir Issues

1. Verifique se já existe uma issue semelhante.  
2. Use os templates disponíveis.  
3. Dê o máximo de contexto possível.  

**Para bugs:**  
- Passos para reproduzir  
- Prints (se houver)  
- Ambiente e ferramentas usadas  
- Resultado esperado vs atual  

**Para sugestões:**  
- Qual problema isso resolveria?  
- Qual valor para a comunidade?  
- Exemplos de uso

## 🟨 Criando um Pull Request (PR)

### 1. Faça um Fork do projeto  
Clique em **Fork** no topo da página do GitHub.

### 2. Crie uma branch descritiva  
Exemplo:

```
git checkout -b feature/refactor-modulo-ia
```

### 3. Faça suas alterações  
Siga as boas práticas listadas abaixo.  

### 4. Descreva claramente o PR  
Seu PR deve conter:

- O que foi alterado  
- Motivo da alteração  
- Prints, resultados ou detalhes relevantes  
- Se há ou não impacto em outros projetos  

### 5. Mantenha o PR pequeno e focado  
Isso facilita revisão e aprovação.

### 6. Seja aberto(a) ao feedback  
PRs costumam envolver conversas e ajustes — faz parte do aprendizado colaborativo.

## 🟩 Padrões e Boas Práticas

### 🧰 Estrutura de Projeto
Cada projeto deve seguir:

```
/nome-do-projeto
  ├── README.md
  ├── src/
  ├── prompts/
  ├── insights.md
  └── resultados/
```

### 📄 README do Projeto — Template
Inclua:

- Objetivo  
- Tecnologias  
- Como rodar  
- Prompts utilizados  
- Processo iterativo  
- Resultados  
- Próximos passos  

### 💬 Prompts
- Salve cada prompt como um arquivo `.md` dentro de `/prompts`  
- Nomeie de forma sequencial:  
  - `01-contexto.md`  
  - `02-primeira-interacao.md`  
  - `03-refinamento.md`  

### 🧼 Código
- Mantenha legibilidade  
- Comente trechos relevantes  
- Evite dependências desnecessárias  
- Explique decisões importantes em `insights.md`

### 📘 Commits
Use mensagens descritivas:

```
feat: adiciona primeiro modelo de geração de textos
fix: corrige erro no script de treinamento
docs: melhora README do projeto 2
refactor: reorganiza prompts do projeto 1
```

---

## 🟥 Revisão e Aceite

Nem todo PR será aceito imediatamente — isso é normal.  
Durante a revisão, podemos pedir:

- Ajustes na descrição  
- Melhor organização de pastas  
- Mais detalhes sobre prompts e aprendizados  
- Separação em PRs menores  

Nosso objetivo é **qualidade + clareza**, não pressa.

## 🟦 Dicas para Iniciantes
